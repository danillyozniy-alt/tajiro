# Tajiro

Страницы сайта Tajiro. Каждая разобрана на исходники, из которых собирается
обратно — и в обычный сайт, и в один файл для отправки.

Сейчас их четыре: главная (`index`), фрибейсик (`free-basic`), оплата
(`checkout`) и вход (`login`). Первые две — лендинги, вторые две — служебные
страницы воронки: на них нет ни шапки, ни подвала, только знак.

---

## Как это устроено

**`src/` — то, что правишь.** Одна секция страницы = один партиал + один файл
стилей (+ свой скрипт, если у секции есть поведение). Ищешь блок глазами на
странице — открываешь файл с тем же номером.

**`dist/` и `send/` — то, что получается.** Целиком генерируются сборкой,
руками туда лезть не надо.

### Три слоя вместо одной кучи

Файлы разложены по тому, **скольким страницам они принадлежат**, а не по типу:

| Папка | Что лежит | Правило |
|---|---|---|
| `core/` | шрифты, токены, появление при прокрутке | фундамент, есть на каждой странице |
| `shared/` | шапка, подвал, полоса показателей, «A complete platform» | блок стоит больше чем на одной странице |
| `<страница>/` | секции только этой страницы | всё остальное |

Правило переезда одно: **файл уходит в `shared/` ровно тогда, когда его
подключает вторая страница, — не раньше.** Пока блок на одной странице, он
живёт в её папке; понадобился на второй — переезжает, и обе берут один файл.
Копий не заводим: копия расходится с оригиналом на первой же правке.

```
tajiro/
├── src/
│   ├── pages/                каркасы страниц: порядок секций и стилей

│   │   ├── checkout/             счёт, поля, платёж

│   ├── css/                  стили — той же раскладкой
│   │   ├── core/                 fonts · base · reveal
│   │   ├── shared/               logo · header · footer · forms · prefs · stats
│   │   ├── home/
│   │   ├── free-basic/
```

### Добавить страницу

1. Положить каркас в `src/pages/<имя>.html`.
2. Завести `src/partials/<имя>/` и `src/css/<имя>/` под её секции.
3. Дописать одну строку в `PAGES` в `tools/build.mjs`.

Дальше сборка сама соберёт и `dist/<имя>.html`, и `send/Tajiro-<имя>.html`.

## Команды

Node уже стоит, ставить ничего не нужно — `npm install` не требуется.

Работать над страницей (собрать, поднять сервер, следить за правками):

```bash
npm run dev
```

Откроется на `http://localhost:4173`. Правишь файл в `src/` — сборка сама
пересобирает `dist/`, дальше обычный F5 в браузере.

Просто собрать оба варианта:

```bash
npm run build
```

После этого файл для отправки лежит в `send/Tajiro-home.html` — тот же самый
цельный html, что был раньше, ничего не потерялось.

## Кадры

Снимки на страницах рисует Gemini Image (Nano Banana Pro). Промпты лежат не в
переписке, а в манифесте `tools/genimg.mjs` — рядом с кодом, и переживают любую
пересборку. Там же записан общий регистр: дневной свет, современный Залив,
тёплые цвета, без платков. Он приписывается к каждому промпту, чтобы новый
кадр встал в один ряд с прежними, а не рядом.

```bash
node tools/genimg.mjs --list
```

Показывает манифест и то, какие кадры уже нарисованы. Без аргументов скрипт
рисует только недостающие; `--force` перерисовывает всё.

Нужен ключ из aistudio.google.com — строкой `GEMINI_API_KEY=…` в файле
`.env.local` в корне (он в `.gitignore`) либо одноимённой переменной окружения.
Ещё нужен `ffmpeg` в PATH: исходник приходит jpg, а в разметке стоит webp, и
пережимает его он.

**Ссылку на ненарисованный файл заводить нельзя.** Сборка ищет пути к ассетам по
всему тексту страницы, включая комментарии, и падает на первом отсутствующем.
Пока кадра нет, место под него держит фактура — см. экран телефона в
`free-basic/08-marketing`.

## Где что менять

`<стр>` ниже — это `home` или `free-basic`.

| Что правишь | Куда идёшь |
|---|---|
| Текст, кнопки, ссылки в секции | `src/partials/<стр>/NN-название.html` |
| Внешний вид секции | `src/css/<стр>/NN-название.css` |
| Цвета, шрифты, отступы, кнопки — общее | `src/css/core/base.css` (токены в `:root`) |
| Шапка и мобильное меню | `src/css/shared/header.css` + `src/js/shared/header.js` |
| Подвал | `src/css/shared/footer.css` + `src/js/shared/footer.js` |
| Появление блоков при прокрутке | `src/css/core/reveal.css` + `src/js/core/reveal.js` |
| Картинку заменить | положить файл поверх старого в `src/assets/img/` |
| Порядок секций на странице | `src/pages/<стр>.html` — переставить строки `<!--#include -->` |
| Title, description, og-теги | `src/partials/<стр>/head.html` |

Правишь что-то в `core/` или `shared/` — меняется **на всех страницах сразу**.
Это и есть смысл этих папок, но перед правкой стоит открыть вторую страницу и
посмотреть, как блок стоит там.

### Оплата и вход

Две служебные страницы воронки. Шапки и подвала на них нет намеренно: любая
навигация уводит человека со страницы, ради которой он пришёл. Из общего они
берут только знак (`shared/logo`) и поля ввода (`shared/forms`).

| Страница | Разметка и стили | Что помнить |
|---|---|---|
| Оплата | `checkout/00-checkout` | Счёт стоит ВЫШЕ полей, и на телефоне тоже: сначала видно, что сегодня не списывают ничего. Поле карты — заглушка с меткой STRIPE ELEMENTS, настоящее рисует Stripe в своём iframe |
| Вход | `login/00-login` | Пароля нет по замыслу: на почту уходит одноразовая ссылка. Два состояния — форма и «письмо отправлено» — лежат в разметке оба |

Что осталось подключить, выписано заметками внизу `pages/checkout.html` и
`pages/login.html`.

Язык и валюта переключаются одним элементом в шапке — `js/shared/prefs.js`.
Он общий для всех страниц: собирает кнопки по `data-lang` и `data-market`,
держит панель в шапке и строку в мобильном листе в одном состоянии и
пересчитывает всё, что помечено `data-usd`, `data-sub`, `data-range`,
`data-week`. На странице без таких пометок просто ничего не находит.

Едущие ленты товаров ведёт `js/shared/roll.js` — один скрипт на каталог
главной и полку фрибейсика. Он не знает классов секций и ищет разметку по
`data-roll`: окно, внутри `data-roll-track` с `data-roll-list`, в нём строки
`data-roll-row`. На окне два параметра: `data-roll-focus` — какая по счёту
строка стоит в полосе подсветки, `data-roll-clones` — сколько копий набора
добавить для бесшовной петли. Копии делает скрипт, а не разметка: в цельном
файле дубли вшили бы те же картинки повторно.

Сам ход делает CSS — у каждой ленты свои `@keyframes`, потому что число
шагов у них разное, а цикла в CSS нет. Скрипту остаётся понять, какая строка
сейчас в полосе, и подсветить её вместе с репликой `data-roll-proof`, если
реплики есть. Шаг он меряет сам и кладёт в `--roll-step` и `--roll-card` на
окне: у полки фрибейсика карточка тянется за содержимым, и зашитое число
промахивалось бы мимо неё на всех ширинах, кроме одной.

## Права на шрифты и знаки

**Шрифты.** Almarai и Outfit — оба под SIL Open Font License 1.1. Она разрешает
коммерческое использование и вшивание в веб-страницы, в том числе base64 в
цельный файл. Ни у одного из них не объявлено зарезервированное имя (Reserved
Font Name): в строке копирайта его нет, только в общем тексте лицензии. Значит,
и семейство `Tajiro Figures` — псевдоним, под которым подключён неизменённый файл
Outfit ради цифр, — лицензии не противоречит.

Тексты лицензий лежат рядом с самими файлами: `assets/fonts/OFL-Almarai.txt` и
`OFL-Outfit.txt`. Их там держат не для красоты — лицензия просит, чтобы файлы
шрифтов расходились вместе с ней, а мы их раздаём с сайта и вшиваем в письма.

**Знаки платёжных систем** (Visa, Mastercard, AMEX, mada, Tabby, Google Pay) —
торговые марки своих владельцев. На странице оплаты они стоят как обозначение
способа оплаты, и это разрешённое использование по назначению. Ставить их
куда-либо ещё — в шапку, в подвал, в рекламу — нельзя без согласия владельцев.

## Два правила, которые лучше не нарушать

**Порядок стилей в каркасе страницы.** Сначала `core/`: там шрифты, токены и
общий механизм появления. Потом `shared/`, потом секции — в порядке страницы.
Переставишь — поедут перекрытия.

**`reveal.js` подключается последним.** Он сначала меряет, что уже в кадре, и
только потом взводит класс `.reveal-armed` на `<html>`. Пока класса нет, ни одно
правило из `core/reveal.css` не срабатывает. Поставишь скрипт выше — блоки успеют
мигнуть невидимыми.

## Тире в текстах сайта

В ВИДИМОМ ТЕКСТЕ ТОЛЬКО СРЕДНЕЕ ТИРЕ, en dash: – (U+2013, в разметке
&ndash;). Длинного, em dash — U+2014, &mdash; — на страницах нет ни
одного, и добавлять новые не нужно: правило общее для всех четырёх
страниц и для текстов, которые появятся позже.

В комментариях внутри файлов остаётся длинное: они написаны по-русски, а
в русском наборе правильное тире именно длинное. Скрипт замены это учёл —
он резал файл на куски и правил только то, что за пределами комментариев.

## Мелочи, о которых стоит знать

- **Комментарии `<!--# ... -->`** в `src/pages/<страница>.html` — записки для себя, в сборку
  они не попадают. Обычные `<!-- ... -->` попадают.
- **Картинки лежат один раз, а на странице встречаются чаще.** Например,
  `icons/check-gold.svg` подставляется в 8 местах, `people/ai-influencer-omar.jpg`
  — в 4. В подключённой сборке браузер скачает такой файл один раз; в цельном
  файле он вшивается на каждое вхождение — отсюда его 3.8 МБ.
- **Цельный файл — это ровно та же страница.** Сборка проверена против исходного
  `Tajiro-home.html`: разметка совпадает символ в символ, стили совпадают,
  скрипты те же, набор картинок и шрифтов идентичен (48 уникальных ассетов).
- **Разобрать собранный файл обратно можно.** Маркеры `<!-- ===== 01-hero ===== -->`
  и `/* ===== 01-hero.css ===== */` сборка расставляет сама — именно по ним этот
  проект и был разобран из первой цельной версии.
